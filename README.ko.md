# excudo-works

Excudo 작업 공간에 일일 자동화와 편집할 수 있는 주간 보고를 더합니다.
사용자가 원칙과 판단 기준을 정합니다.
Node 22.16 이상과 Excudo `^0.7.0`이 필요합니다.

macOS, Linux와 Windows에서 실행합니다.

## 시작

엔진과 키트를 설치한 뒤 작업 공간을 만듭니다.

```sh
npm install --save-dev excudo@^0.7.0 excudo-works
npx --no-install excudo-works init my-work --locale ko
cd my-work
npm install --save-dev excudo@^0.7.0 excudo-works
npx --no-install excudo-works doctor
npx --no-install excudo-works run --manual --only report
```

`init`은 새 폴더에서 엔진 초기화를 먼저 실행합니다.
엔진을 실행할 수 없으면 필요한 명령을 출력합니다.
기존 설정과 사용자 파일은 보존합니다.

스킬 링크를 쓰기 전에 안내한 설치 명령을 실행합니다.

## 명령

작업 공간에서 실행하거나 `--root <폴더>`를 붙입니다.

| 명령 | 하는 일 |
| --- | --- |
| `init <폴더> [--locale en\|ko]` | 빠진 설정과 스킬 링크 생성 |
| `doctor [--json]` | 설치 상태 확인과 수정 방법 안내 |
| `run [--manual] [--only <단계>]` | 일일 자동화 실행 |
| `update [--apply]` | 새 버전 확인과 기록 마이그레이션 |
| `improvements close <id>` | 끝낸 개선 요청 닫기 |
| `feedback` | 공유할 이슈 초안과 주소 출력 |

`update`는 네트워크가 없어도 로컬 기록과 링크를 갱신합니다.
설치된 버전의 변경 기록과 새 버전 설치 명령을 보여 줍니다.
`--apply`는 안내한 설치 명령을 실행한 뒤 새 버전을 별도 프로세스로 띄워 링크와 기록을 갱신합니다.

`feedback`은 초안만 만들며 외부로 보내지 않습니다.

## 설정

엔진 설정의 `works` 키나 `works.config.mjs`에 자동화 설정을 적습니다.
별도 파일이 있으면 그 파일의 설정을 사용합니다.

```js
export default {
  timeoutMs: 120000,
  agentTimeoutMs: 1200000,
  manualWindowMinutes: 60,
  steps: [],
  disabled: [],
  report: { file: 'weekly.md', days: 7 },
  review: false,
  backup: false,
  home: false,
  scheduler: false,
  notifications: false,
}
```

기본 단계는 출처 갱신, 직접 편집 반영과 회고로 시작합니다.
이어서 스킬 관리와 작업 큐 확인을 마치고 보고서를 씁니다.
출처 갱신과 회고는 엔진에 설정한 작업자가 맡습니다.

작업자는 `npx --no-install excudo agents`로 설정합니다.
작업 큐 단계는 목록만 읽습니다.

`steps`에 셸 명령이나 Node 스크립트를 추가할 수 있습니다.
같은 이름의 기본 단계는 적은 항목만 바꾸고 나머지 기본값은 유지합니다.
`disabled`에 단계 이름을 넣으면 실행하지 않습니다.

설정 전체와 예시는 [영문 안내](README.md)를 따릅니다.

활동에는 `conversations`를 켰을 때 엔진이 모은 커밋과 에이전트 세션이 나옵니다.
이 설정이 꺼져 있으면 엔진의 작업 폴더에서 Git 커밋을 읽습니다.
`doctor`가 이 전제를 안내합니다.

## 실행 기록

예약 실행은 그날 성공한 단계를 건너뜁니다.
`daily: false`인 단계는 매번 실행합니다.
전체 수동 실행이 모두 성공하면 정한 시간 안의 다음 예약 실행을 한 번 건너뜁니다.

일부 단계만 실행했거나 실패하면 이 표시를 남기지 않습니다.

실행 잠금과 상태는 `.excudo/works/`에 남깁니다.
로그는 `.excudo/logs/`에 저장합니다.
최종 백로그는 `.excudo/reports/works-backlog.md`입니다.

개별 스킬도 같은 실행 잠금을 사용합니다.
같은 호스트에서 소유 프로세스가 종료된 잠금은 자동으로 회수합니다.
소유자를 알 수 없거나 실행 중이면 잠금을 보존합니다.

상태와 로그 폴더는 엔진의 `cache` 설정을 따릅니다.
위 경로는 기본 캐시 폴더를 쓴 예입니다.
각 단계는 엔진의 실행 기록에도 남아 홈에서 확인할 수 있습니다.

## 보고서 편집

보고서의 작업 표시를 남겨 둔 채 제목이나 상태를 고칩니다.
다음 실행은 편집한 보고서와 마지막 생성 스냅샷을 비교합니다.
반영 직전에는 요청 당시의 원본 줄과 위치도 대조합니다.

원본이 그대로이고 정책이 허용한 편집만 반영합니다.
예약 실행은 엔진의 편집 보류와 그래프 잠금을 따릅니다.
보고서 생성은 원본을 바꾸지 않습니다.

개별 스킬을 예약 실행할 때는 `--scheduled`를 붙입니다.
사용자 단계는 루틴의 예약 실행 여부를 이어받습니다.

반영한 메모 파일은 `excudo save --only`로 그 파일만 커밋합니다.
저장이 실패하면 그 파일을 "확인할 것"에 표시하고 다음 edits 단계에서 다시 저장합니다.
키트가 쓴 파일 때문에 뒤 단계가 보류되는 일을 막습니다.
다른 사용자의 변경 파일은 커밋에 넣지 않습니다.

충돌과 삭제 요청은 결정을 기다리는 항목으로 남깁니다.

`policy.json`은 완료 처리를 검토 대상으로 둡니다.
`allowCompletion: true`를 설정하면 보고서에서 지정한 완료도 반영합니다.
보류된 편집 질문에 ` // 적용`으로 답하면 그 요청만 승인합니다.

요청 뒤 원본이 바뀌었으면 승인해도 자동 반영하지 않습니다.
줄 끝에 ` // 답변`을 적으면 코멘트로 받습니다.
설정한 작업자는 읽기 전용으로 코멘트를 판단합니다.

검증한 제목과 상태 변경만 반영합니다.
모호한 요청은 사용자 결정으로 남깁니다.
` // improve: 요청`은 코드 개선 요청으로 기록합니다.

질문에 ` // 완료`나 ` // 무시`로 답하면 해당 항목을 닫습니다.
답을 처리하면 원래 질문도 정리합니다.
끝낸 개선 요청은 `npx --no-install excudo-works improvements close <id>`로 닫습니다.

생성 구역 밖에 쓴 내용은 그대로 보존합니다.
구역 표시가 빠지거나 겹치면 보고서 생성을 멈춥니다.
생성 도중 보고서를 고치면 덮어쓰지 않고 재시도를 요청합니다.

다른 직접 편집은 `.excudo/works/`의 스냅샷에 보존합니다.
날짜 없는 완료 항목은 파일 수정 시각을 쓰므로 보고 전에 확인합니다.

## 원칙과 검토

사용자 원칙은 AGENTS.md와 `invariants.json`에 같은 글로 둡니다.
사용자가 원칙 변경을 승인했을 때만 두 곳을 바꿉니다.
두 글이 다르면 실행을 멈춥니다.

지침 크기는 엔진의 `instructions --check --json`으로 확인합니다.
한도 초과는 백로그 경고로 남기고 정리 단계는 계속 실행합니다.
`--force`도 사용자 원칙은 바꾸지 않습니다.

`review`를 켜면 엔진의 검토자 설정으로 주간 읽기 전용 검토를 실행합니다.
검토 의견은 별도 보고서에 남깁니다.
개선 스킬은 검토할 작업자 명령과 병합 명령을 출력합니다.

작업자 실행과 병합은 사용자가 결정합니다.

작업자 단계의 기본 시간 제한은 20분입니다.
단계의 `timeoutMs`를 정하면 안쪽 작업자에도 같은 값을 전달합니다.
`workerPermissions`에서 권한을 정하고 `doctor`로 확인합니다.

Claude는 제한한 도구 목록과 `acceptEdits`를 기본으로 씁니다.
Codex는 `workspace-write` 샌드박스를 기본으로 씁니다.
개선 스킬은 `improvePermissions` 권한으로 대화형 명령을 출력하며, 사용자가 직접 실행합니다.

## 선택 기능

필요한 기능만 설정에서 켭니다.
예약 실행은 `doctor`가 만든 운영체제별 등록 안내를 따릅니다.
알림은 사용자가 고른 명령에 실행 결과를 전달합니다.

홈 검사는 개인 계획 위쪽과 업무 쿼리 아래쪽의 순서를 확인합니다.
홈을 자동으로 재배치하지 않습니다.

암호화 백업은 사용자가 정한 폴더에 저장합니다.
비밀번호는 환경 변수나 운영체제의 자격 증명 저장소에서 읽습니다.
macOS는 `keychainService`, Linux는 `secretService`를 설정합니다.

Windows는 자격 증명 관리자의 일반 자격 증명 이름을 `credentialName`에 적습니다.
비밀번호를 출력하거나 파일로 저장하지 않습니다.
복원은 현재 작업 공간 밖의 새 폴더에서만 합니다.

예약 실행 계정에서 자격 증명 저장소를 열 수 있어야 합니다.
Linux는 `secret-tool`과 잠금이 풀린 Secret Service 세션이 필요합니다.
환경 변수를 쓰면 예약 서비스 환경에 별도로 공급하고 `scheduledEnvironment: true`를 설정합니다.

비밀번호를 예약 명령이나 파일에 적지 않습니다.
안전한 출처가 없으면 `doctor`가 경고합니다.

백업은 엔진이 만든 일관된 캐시 사본을 사용합니다.
의존성 폴더와 Git 메타데이터, 심볼릭 링크는 제외합니다.
파일 크기를 먼저 확인한 뒤 내용을 읽습니다.

기본 입력 한도는 128 MiB입니다.
`backup.keep`은 기본 30개이며 이 작업 공간의 백업만 정리합니다.
큰 작업 공간은 별도 암호화 백업 명령을 단계로 등록합니다.

푸시 방지 스킬은 비공개 작업 공간의 모든 일반 푸시를 막습니다.
기존 훅은 옆에 보관합니다.
이 저장소의 Git 폴더 밖에 있는 공용 훅과 추적 파일은 바꾸지 않습니다.

스킬에 `remove`를 넘기면 이전 훅을 복원합니다.
공개할 때는 별도 클론으로 내보내고 검토합니다.
특정 편집기나 이슈 추적기, 클라우드 서비스는 필요하지 않습니다.
